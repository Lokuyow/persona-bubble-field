> この文書は本プロジェクトの確定仕様の一部です。Source of Truthの入口は [`docs/PROJECT.md`](../PROJECT.md) とし、本資料を含む同資料記載の `SPEC-*` 文書一式と併用する。個別仕様は、その仕様を記載する文書を正とする。

## 8. キャラクター割当

キャラクターは事前に複数用意する。

バックエンドへ割当結果を保存しない。

新規生成されたNostr pubkeyから、決定的にキャラクターを導出する。

同じpubkeyからは常に同じキャラクターが導出される。

Nostr鍵自体がランダム生成されるため、正規UIを通常どおり利用するユーザーから見るとランダムなキャラクター抽選として扱う。

ただしバックエンドがないため、以下の行為は完全には防止できない。

- 大量の鍵ペアを生成する
- 希望するキャラクターが出るまでpubkeyを探索する
- 正規UIを使わず任意の鍵を使用する
- 改造クライアントで抽選処理を回避する

**キャラクター抽選の暗号学的な公平性は保証しない。**

キャラクター抽選および24時間転生制限は、通常ユーザー向けのUXルールとして扱う。

### キャラクターごとの出現確率

個々のキャラクターにレアリティや個別の出現重みは設けない。

特定のキャラクターを「レアキャラ」「当たり」「ハズレ」として、他のキャラクターより意図的に出やすく・出にくくする設計にはしない。

カテゴリごとの出現割合は、主としてそのカテゴリに属するキャラクター数によって調整する。

例えば、人間キャラクターを多く用意すれば人間全体の出現割合は高くなり、少数しか用意しないカテゴリは結果として出現割合が低くなる。

導出方式を設計する際も、個々の `characterId` に意図的な重み差を持たせない。

### 導出規則の固定

pubkey → characterの対応は、既存ユーザーの専用世界での人格そのものである。

そのため公開前に、少なくとも以下を確定し、テストfixture等によって固定する。

- 導出アルゴリズム
- アプリ固有の導出用識別文字列等
- character slot数
- slot順
- slot → characterId の対応

導出方式にversion識別子を含めることはできるが、**versionを変更するだけで既存pubkeyのキャラクターを変更してよいものとはしない。**

公開後は、既存pubkey → characterの対応が変化しないよう互換性を維持する。

## 9. キャラクターデータ

キャラクターには最低限、以下を持たせる。

- characterId
- name
- about
- picture

必要に応じてmetadataやアクセシビリティ情報、表示補助情報を追加できる。

キャラクターの公式な人格設定は、原則としてこの最小構成を基本とする。

年齢、性格、口調、好き嫌い、経歴、過去、行動規範等を全キャラクター共通の必須設定にはしない。

必要なキャラクターについて個別に補助的な設定を持たせることは禁止しないが、ユーザーへ詳細な設定どおりのロールプレイを要求する設計にはしない。

キャラクターは、

> **設定された人物を忠実に演じるための役ではなく、与えられた別人格として会話を始めるためのきっかけ**

として扱う。

### キャラクターの幅

キャラクターは、特定の種族・世界観・人型に限定せず、大きな幅を持たせる。

例えば以下のようなカテゴリを含めることができる。

- 通常の人間
- 役割・立場
- 動物
- ファンタジー
- 怪異・アンデッド
- 非生物
- 植物・菌類
- 食べ物
- 機械・人工物
- その他の分類しにくい存在

例えば、

- 猫
- オオアリクイ
- エルフ
- ドラゴン
- 幽霊
- 石ころ
- 道に落ちてる軍手
- 自動販売機
- お母さん
- 通常の人間

等が同じキャラクター体系に混在してよい。

奇抜な存在だけで構成せず、通常の人間や一般的な動物等も十分に含める。

普通の存在、少し変わった存在、かなり変わった存在が同じ世界に自然に混在する状態を目指す。

### 人間キャラクター

通常の人間キャラクターは、現実に存在しそうな人物を基本とする。

一方で、

- 会社員っぽい人
- 知らないおじさん
- 妙に姿勢のいい人

等、少しだけズレや特徴を持つ人物も混在させてよい。

人間キャラクターまで全員を強いネタキャラクターにする必要はない。

通常の人物を世界の基準点として残すことで、動物、ファンタジー、非生物等の異質さも維持する。

人間キャラクターの文化圏は日本だけへ限定しない。

日本を含む世界中の文化・地域・名前・服装等を自然に混在させる。

ただし、各国・各地域から機械的に同数ずつ用意する等の厳密な均等配分は要求しない。

### 名前

キャラクター名には、

- 普通名詞
- 種類・役割そのものを表す名前
- 特徴を含む呼称
- 固有名詞

を自由に混在させる。

例えば、

- 猫
- 太った猫
- 石ころ
- お母さん
- ミケ
- ミナ

等が同じキャラクター体系に存在してよい。

種族・役割・特徴・固有名をすべて名前へ含める必要はない。

`太った猫 ミケ`、`エルフ フリーダ` 等の「種類 + 固有名」の形式へ機械的に統一しない。

キャラクターごとに、そのキャラクターを最も自然または面白く表現できる一つの呼称を採用する。

名前はフィールド上のキャラクターアイコン付近へ小さく表示されるため、原則として簡潔なものを優先する。

ただし、キャラクターとして成立する場合に多少長い呼称を使用することは禁止しない。

キャラクターマスター内では、別キャラクター同士に同一の `name` を使用しない。

同じキャラクターが複数pubkeyへ割り当てられ、同じ `name` のユーザーが同時に存在することは別の概念として許容する。

### about

`about` は、そのキャラクターを想像するための短いプロフィールとして扱う。

ユーザーへ特定の口調や行動を強制する演技指示書にはしない。

文章のトーンは全キャラクターで統一しない。

キャラクターに応じて、

- 淡々とした説明
- 軽いユーモア
- 真面目な文章
- 一人称
- 詩的な文章
- その他、そのキャラクターに合う短い表現

等を自由に使用してよい。

ただし、全キャラクターに詳細なバックストーリーや長文設定を要求しない。

### 派生・コンパチキャラクター

同じ種類・原型・素体を利用した派生キャラクターを複数用意してよい。

例えば猫であれば、

- 猫
- 太った猫
- やたら姿勢のいい猫
- ミケ

等を別キャラクターとして扱うことができる。

画像制作上、基本素体、構図、ポーズ等を共有することも許容する。

ただし、単なる色違いだけを理由に別キャラクターを大量に増やさない。

派生キャラクターとして追加する場合は、少なくとも `name`、`about`、`picture` 等から読み取れるキャラクター性に、別個体として認識できる明確な差を持たせる。

コンパチによる制作効率化は許容するが、水増しそのものを目的にはしない。

### キャラクター画像

キャラクター画像は、全体として同じサービス・同じ世界に存在するキャラクターとして見える程度の基本的な統一感を持たせる。

配信用キャラクター画像は、以下の仕様とする。

- サイズは 512×512 px とする。
- 形式は WebP とする。
- 背景は透明とする。
- キャラクターに伴う影は画像内に含める。

制作原画は 512×512 px より高解像度で作成・管理し、配信用画像とは分離して管理する。制作原画の具体的な解像度、保存場所、ファイル形式等は別途決定する。

画像の構図は全キャラクターで統一せず、顔中心、バストアップ、全身等の複数の構図を混在させてよい。顔中心の構図を最も多くする方向とし、各キャラクターに最も適した構図を選択する。

人間、動物、非生物、ファンタジー等を完全に同じ構図・頭身・表現へ強制しない既存方針は維持する。

具体的な画風、顔中心・バストアップ・全身等の構成比、制作原画の具体的な仕様、その他今回確定していない画像制作方法の細部は未決定とする。

### 歴史・伝承・既存作品・実在人物

現代の実在人物や、漫画、アニメ、ゲーム、映画、小説等の既存作品に属する固有キャラクターを、原則として本サービスのキャラクターとして採用しない。

一方で、

- 歴史上の人物
- 神話上の人物・存在
- 民間伝承上の人物・存在

は候補にできる。

歴史上の人物については、

- 本人そのものをキャラクターとして扱う
- その人物や時代をモチーフにしたオリジナルキャラクターとして扱う

の両方を許容する。

例えば、実在した歴史人物の固有名をそのまま使用することも、その人物を直接指さない「天下人」「古代の女王」等のモチーフキャラクターを作ることもできる。

神話・民間伝承についても、河童、天狗、鬼、メドゥーサ、ケルベロス等の存在を候補にできる。

ただし、現在も広く信仰されている宗教の中心人物・中心的神格そのものを、ランダムに割り当てられるキャラクターとして扱うことは避ける。

### 現実の人間属性

年齢、職業、家族上の役割、生活上の立場等、現実の人間属性をキャラクター要素として利用してよい。

病気、障害、民族、宗教、経済状態等、センシティブになり得る属性についても一律には禁止しない。

ただし、属性そのものや弱い立場にあることだけを笑いの理由としたり、侮辱的・蔑視的なキャラクターとして扱ったりしない。

その属性を用いる場合は、個別のキャラクターとして自然に成立しているかを判断する。

### カテゴリ構成

キャラクターのカテゴリ比率には目標値を設けてよい。

例えば、

- 人間や動物は比較的多め
- 非生物も十分な数を確保する
- 分類しにくい存在は少数にする

等、世界全体のバランスを確認するために使用する。

ただしカテゴリ比率は制作ノルマとして固定しない。

良いキャラクター案を比率に合わせるためだけに削除したり、数合わせのために品質の低いキャラクターを追加したりしない。

制作途中ではカテゴリごとの件数を集計し、極端な偏りがあれば新規案の方向性を調整する。

最終的なカテゴリ構成は、目標比率だけでなくキャラクター全体の質を優先して決定する。

具体的なカテゴリ分類、カテゴリごとの目標比率、最終的な収録数は未決定とする。

### 原則固定するもの

公開後、そのキャラクター体系において以下は原則変更しない。

- characterId
- 名前
- 基本プロフィール
- キャラクターの同一性に関わる情報

また、キャラクター割当に影響する以下の構造も固定する。

- character slot数
- slot順
- slot → characterId

これらを変更して既存ユーザーの人格が変化することを避ける。

### 後から変更可能なもの

人格の同一性を壊さない範囲で、以下は変更可能。

- 誤字修正
- metadata
- アクセシビリティ情報
- 表示補助情報
- その他、キャラクターの同一性に影響しない細かな修正

### キャラクター画像URL

キャラクター画像URLは固定する。

画像を改善・描き直す場合も、原則として同じURLを維持する。

画像内容の変更は、同じキャラクターであることが明確な範囲に留める。

## 10. キャラクターの重複

バックエンドなしのため、同じキャラクターが複数のpubkeyに割り当たることを許容する。

必要になった場合は、同じキャラクターが同時に表示される場面だけpubkey由来の短い識別子を表示する等の対策を検討する。

キャラクター重複を防止するための中央割当DBは導入しない。
